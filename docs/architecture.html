Module 02 · REST API · FastAPI + Pydantic v2

Lab Sample Registry API

A small, production-style REST service that stores DNA samples and exposes CRUD over HTTP. Storage is in memory today; the next module swaps it for SQLAlchemy 2.0 + Postgres without touching a single endpoint.

Each layer talks only to its neighbour. Routers see a Protocol, never a concrete store.
The one rule: routers never import storage code; repositories never import FastAPI. Because routers depend on the SampleRepository Protocol, the storage engine is a detail that can change behind the interface.

Request lifecycle

Follow one POST /samples from wire to response.

sequenceDiagram
    participant Client
    participant FastAPI
    participant Router as create_sample
    participant DI as get_repository
    participant Repo as InMemorySampleRepository
    Client->>FastAPI: POST /samples {name, organism, sequence}
    FastAPI->>FastAPI: parse body into SampleCreate
    alt invalid body
        FastAPI-->>Client: 422 with error details
    end
    FastAPI->>DI: resolve RepoDep
    DI-->>Router: repository (singleton)
    Router->>Repo: add(payload)
    alt name already used
        Repo-->>Router: DuplicateNameError
        Router-->>Client: 409 Conflict
    end
    Repo-->>Router: Sample (id, created_at set)
    Router->>Router: SampleRead.model_validate(sample)
    Router-->>Client: 201 Created, Location: /samples/{id}
  1. Validation happens before your code runs. If the body does not match SampleCreate, FastAPI returns 422 and the route function is never called.
  2. Dependencies are resolved per request. RepoDep calls get_repository(), which is cached, so every request sees the same store.
  3. Domain errors become HTTP errors in the router. The repository raises a plain DuplicateNameError; only the router knows that means 409.
  4. Output goes through a response model. SampleRead.model_validate(sample) reads the dataclass attributes (from_attributes=True) and adds computed fields.

For routes with {sample_id}, the SampleDep dependency (get_sample_or_404) parses the UUID, loads the sample and raises 404 if it does not exist. The route body only ever sees a real Sample.

Data models

There are two kinds of model, and keeping them apart is the main lesson of the module.

DTOs · Pydantic

schemas.py. The public contract over the wire: what may come in, what goes out.

Domain object · dataclass

Why separate input and output models? If one model served both directions, a client could send its own id or created_at, and derived values like gc_content would have to be stored and kept in sync. Splitting them makes the contract explicit and safe.

REST API design

MethodPathSuccessErrors
GET/samples?organism=&limit=&offset=200 Page422
POST/samples201 + Location409 422
GET/samples/{id}200 + _links404 422
PATCH/samples/{id}200404 422
DELETE/samples/{id}204 empty404
GET/health200 status ok
  • Nouns in paths, verbs in methods. One resource (/samples), one router.
  • Status codes carry meaning. 201 plus Location tells the client where the new resource lives; 204 means success with nothing to return; 409 means the request conflicts with current state (duplicate name); 422 means the input is malformed.
  • Filtering and pagination via query parameters. limit is 1 to 100 (default 20), offset is 0 or more; total lets clients compute the number of pages.
  • PATCH is a partial update. The repository applies only fields the client actually sent (model_dump(exclude_unset=True)), so omitted fields stay untouched.
  • Richardson Maturity Level 3 (HATEOAS). GET /samples/{id} returns _links with self, update, delete and collection. Clients follow links instead of building URLs; request.url_for keeps them correct if prefixes change.

Testing

tests/test_samples.py uses FastAPI TestClient, which calls the app in process: no server, no network.

app = create_app()
repo = InMemorySampleRepository()
app.dependency_overrides[get_repository] = lambda: repo

This is where Dependency Injection pays off: each test gets a brand new, empty repository, so tests never share state. Coverage includes the happy path and every documented error: 201 + Location, 422 for bad sequence, organism and name, 409 on duplicates, the full CRUD lifecycle, filtering + pagination, 404 on unknown id, and following a hypermedia link.

Conventions live in tests/CLAUDE.md. End-to-end tests with Robot Framework against a running server are planned in e2e/.

Quality gate

uv run python scripts/check.py runs these steps and stops at the first failure. The summary is short; full output goes to .claude/logs/check.log.

  1. dashes: no em or en dash characters in project text files (house style)
  2. pytest
  3. ruff lint
  4. mypy strict on app/

.claude/settings.json wires Claude Code hooks: uv sync on session start, a guard that forces uv run instead of bare pip or python, auto format + lint and a dash check after every edit, and a check run when a session stops.

Limits and next steps

In-memory store limitations

  • Data is lost on restart and not shared between worker processes.
  • No locking, so concurrent writes are not safe.
  • The duplicate name check scans every item (O(n)); a database would use a unique index.

Exercises
